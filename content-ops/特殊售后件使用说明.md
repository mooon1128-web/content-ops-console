# 特殊售后件与岗位分工

本次实现于本地源代码，线上版本、员工账号尚未变更。现有经营协作台增加“特殊售后件”入口；原普通售后出入库继续保留。同一个平台售后编号只能登记在一个入口。

## 谁负责什么

| 岗位 | 工作内容 | 库存处理权限 |
| --- | --- | --- |
| 客服 | 建工单、认领未知来件、确认原单与处理要求、指定内部负责人和跟进日期、核对结案 | 可登记方案，不能确认出入库 |
| 仓管 | 收件、记录存放位置、维修进度、原件寄回、新品补发、旧件验收转库、周六盘点 | 实际动作确认后入账 |
| PR | 查询商品库存、寄样进度；在原博主推广系统维护合作 | 不能直接扣库存 |
| 新媒体运营 | 查看净销量和库存，安排内容；继续使用原内容账号分配 | 不能直接扣库存或改写净销量 |
| 经营数据运营 / 管理员 | 原有SKU、月销和核对工作；管理员分配权限 | 沿用原权限 |

客服、仓管、经营数据运营、管理员可以读取特殊件工单；PR与新媒体运营不读取工单内容。成本原表仍仅管理员可看。岗位分配不会自动开通原博主系统账号，也不会改变原内容账号分配。本次没有创建真实员工账号。

## 每张工单记录什么

工单编号、平台、原订单号、原件SKU、需补发SKU、处理类型、预计退回数、需补发新品数、内部负责人、下次跟进日、处理要求、下一步事项；收件后增加存放位置，以及每次交接的时间、件数、单据或运单编号、经手人和依据。

使用原订单系统查看寄回地址，此台账不设置消费者姓名、电话、地址字段。自由文本也不要粘贴这些信息。

一张工单对应一个原件SKU。多款售后按不同后缀拆分工单，保留原售后编号关联。建议在实物包装上贴工单编号。同一工单在手件存放在同一个位置，移位须更新进度留痕。

## 四种处理流程

1. **维修原件寄回**：客服建单 → 仓管确认收件并记位置 → 维修中 → 验收完成标“待寄回” → 登记原件寄回单号和数量 → 客服核对结案。整条流程不增加或扣减公司库存。
2. **换货 / 等货补发**：客服分别填写退回数与新品补发数 → 仓管收到旧件后暂存特殊件区 → 旧件验收转入合格或待检库存 → 实际新品寄出时记补发出库 → 客服核对结案。等待补货时更新为“待到货”；收旧件与发新品可以分别处理。
3. **缺件 / 补发**：预计退回填0，登记实际新品SKU与待补数量 → 仓管确认实际新品出库 → 客服核对结案。不新增销售，也不自动改写月净销量。
4. **来件待认领**：仓管可暂缺订单、SKU建立工单并登记收件位置与来件编号 → 客服根据原系统单号/退回运单认领，确定维修或换货方案 → 再继续处理。认领前不能寄出或转入公司库存。

“工单已建立”不代表收到了货。只有仓管的收件交接才计入工单在手数量。

## 库存与防重复规则

- 客户维修原件和未验收转库的换货旧件属于特殊件暂存账，不纳入公司商品可售、待检库存，也不要混入周六商品盘点。
- 合格换货旧件转库增加合格库存；转待检只增加待检库存；原件寄回只减少特殊件在手数。
- 新品补发必须已有对应仓库的库存盘点基准，实际出库才扣合格库存，预留按本次实际释放数处理。任何动作不得导致负库存。
- 已进入最新实盘基准的历史出入库不能再次补记扣加；先登记待核事项，由负责人核对。
- 同一工单的同一动作与单据不重复登记；处理件数不能超过剩余数量；有实物动作后不能随意更换原单、SKU、处理类型。更改方案保留前后内容。
- 未收、未寄、未转库或未补发的数量没有核清不能结案。结案后不再执行实物动作，新一轮售后另开工单。

## 待办与导出

页面可以查工单、原订单、运单、负责人和存放位置；筛选未结案、待认领、等货补发、库存足够待补发或全部。跟进日已过会在页面显示。

“库存足够待补发”按每张工单的剩余补发数与新品SKU默认仓当前可售库存比较。它只是逐单提示，**不自动预留或寄货，不代表多张工单同时都有足够库存**。仓管需按实际顺序核对；库存在其他仓时另行核实。还没有实盘基准时保持未知。

可分别导出“特殊售后件台账”和“交接记录”CSV，用Excel打开。导出遵循当前筛选范围，包含每次方案变更及经手人；“全部（含已完成）”可导出完整历史。

当前没有站外催办消息、物流自动查询或后台自动补发。跟进提示在刷新页面后更新。
